### 核心架构约束

| 规则 | 说明 |
|------|------|
| DDD 依赖方向 | `domain/* → framework/* → models/`，domain 间禁止互相 import |
| 异步 | 所有 DB 操作异步（aiomysql + SQLAlchemy 2.0 async） |
| 装饰器注册 | 指标/策略/估值/Agent 均通过装饰器自动发现 |
| SQLite 宽表 | 技术指标 + 财务指标各一张宽表，动态 DDL |
| 搜索代理 | 全部走 Clash 127.0.0.1:7890 |
| 前端 API | `API_BASE=/api`，禁止硬编码路径 |

## 三、战略愿景

> 把 AI 的分析能力、系统的基础数据能力、人的决策判断能力，以模块化方式组织成一套可进化的操作系统。

### 3.2 核心原则

1. **渐进式复杂** — 地基做扎实再盖上层。先有数据，再有分析，后有决策，最后自动化
2. **个人级务实** — 免费接口的现实约束下追求最优体验，不追求实时全量
3. **模块自治** — 每个模块可以独立演进，通过接口而不是共享状态协作
4. **AI First** — 凡是 AI 能做的（定性判断、模式识别、总结提炼）交给 AI，系统做确定性的计算和存储
5. **可观测** — 每一层都有健康检查和数据质量指标

### Phase 2 — 智能层延伸（Phase 1 之后，预估 3-5 周）

**目标**: 从"工具有"到"能自动干活"

#### 2.1 Agent 注册机制

| 问题 | 方案 |
|------|------|
| 每加一个 Agent 都要改 `routes.py` | 建立 AgentRegistry (类似 INDICATOR_REGISTRY) |
| 新 Agent 需要 import + 手工路由注册 | 装饰器 `@register_agent` + 自动发现 |

**设计**:
```python
# framework/agents/registry.py
AGENT_REGISTRY = {}

def register_agent(name, category="research"):
    def decorator(cls):
        AGENT_REGISTRY[name] = cls
        cls.agent_name = name
        cls.agent_category = category
        return cls
    return decorator
```

**涉及新增**: `backend/app/framework/agents/registry.py`

#### 2.2 消费类投研 Agent

**定位**: 与 Step 2 MarketScanner 并列，但聚焦消费/需求侧行业

| 维度 | MarketScanner (现有) | ConsumerAgent (新增) |
|------|---------------------|---------------------|
| 分析行业 | 供给侧 (半导体/AI/能源) | 需求侧 (消费/医疗/互联网) |
| 核心逻辑 | 产能瓶颈+技术壁垒 | 品牌力+渠道+用户粘性 |
| 输出框架 | 6-Block 瓶颈图谱 | 4P 营销分析 + 波特五力 |
| A股映射 | 产业链上下游 | 品牌矩阵+渠道网络 |

**涉及新增**: `backend/app/domain/research/agents/consumer_agent.py`

## 五、架构决策记录

### ADR-001: Agent Registry 模式

**决策**: 建立统一 AgentRegistry（类似 INDICATOR_REGISTRY），装饰器自注册
**原因**: 当前每加 Agent 改 routes.py，未来 20+ Agent 无法维护
**时机**: Phase 2 开始前
**影响**: 所有现有 Agent 需要加一行装饰器，routes.py 改为自动发现

### ADR-002: 超级交易员为独立 domain

**决策**: `domain/simulated_trading/` 新 domain，不嵌入 Portfolio 或 Quant
**原因**: 职责不同 — Portfolio 管真实持仓，Quant 算指标信号，Trader 做决策执行
**依赖方向**: Trader → Portfolio(读) + Quant(读) + Research(读)，不反向写入

### ADR-003: 搜索工具独立于数据源

**决策**: `framework/tools/` 独立目录，每个工具封装搜索→结构化提取
**原因**: 区别于 `market_data/sources/`（原始行情数据），tools 是高质量语义数据
**重用的现有代码**: `data_loader.py` 中的 `web_search()` / `deep_search()`

### ADR-004: 模拟交易优先于实盘

**决策**: V1 只做模拟，验证策略有效性后再接实盘
**原因**: 避免实盘亏损风险，且模拟回测可验证策略历史表现
**迁移**: V1 持仓表 + V2 券商适配器模式

### ADR-005: 前端解耦以 `js/pages/` 目录为标准

**决策**: 大型页面 JS 从单文件拆到 `js/pages/<page>/` 子模块
**原因**: 现有 tech_indicators.js (1007行) / financial_indicators.js (966行) 已影响可维护性
**标准**: 遵循现有 `frontend-pattern.md` 的 `DataTabs` 命名空间模式

## 七、Session 协作协议

### 7.1 Session 类型定义

| 类型 | 加载上下文 | 适用场景 | 规模 |
|------|-----------|---------|------|
| **全域 Session** | CLAUDE.md + 全部 rules + 全部 memory | 跨域改动，架构决策，复杂链路 | ~15K tokens |
| **领域 Session** | CLAUDE.md + 对应 rules + 相关 memory | 单一领域内部深挖 | ~8K tokens |
| **前端 Session** | 前端规范 + 对应 API 文档 | 纯 UI 改动 | ~4K tokens |
| **修复 Session** | 目标文件 + 最小上下文 | 单 bug 修复 | ~2K tokens |

### 7.2 切换决策树

```
开始新任务
  ├─ 涉及 ≥2 个领域？ → 全域 Session
  ├─ 只改 <领域> 内部？ → 领域 Session
  ├─ 只改前端？ → 前端 Session
  ├─ 单 bug / 单文件？ → 修复 Session
  └─ 否则 → 全域 Session (默认)
```

### 7.3 信息传递

| 载体 | 写什么 | 什么时候写 |
|------|--------|----------|
| git commit | 代码改动 | 每个 Session 结束时 |
| memory/ | 架构决策 / 踩坑 / 待办 | 子 Session 结束时 |
| CLAUDE.md | 架构规则变化 | 涉及架构/目录/依赖方向变化时 |
| 本文档 | 路线图 / 规划变化 | 路线图调整时 |

### 7.4 子 Session 启动模板

```
项目：AIStock Pro V5.16（E:\workspace\AIResearch\AIStock_Pro）
领域：<Quant / Research / Market Data / Portfolio / Frontend>
任务：<具体描述>
请先读 CLAUDE.md 了解全景，再读 .claude/rules/<对应领域规范>，
然后读 memory/ 中相关记忆，最后开工。
```
