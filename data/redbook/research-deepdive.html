L3

层间接口规范：第二层 → 第三层通过 asset_search_queries 传递搜索线索，不得跨层直接读取内部结构。

三路径分叉 | User in the loop 决策

Pipeline 在 Step 2 完成后，用户根据 MarketScanner 输出的认知差强度选择路径：

A

直挖 POST /direct-asset-mine

从 transmission_order 节点直接挖标的，跳过产业链深挖。适用于产业逻辑强但认知差弱、市场已定价的场景。

B

二阶推演 SecondOrderExtrapolator

外推相邻产业的预期差，寻找市场未定价的机会。适用于主产业预期差弱，但存在跨产业溢出潜力。

C

深挖（标准链路） Step 3 → 4 → 5 → 6

标准全链路穿透：产业链拆解 → 系统动力学 → 跨产业关联 → 核心资产筛选。适用于认知差强的产业。

核心设计原则

LLM 做定性归类

不输出不可验证的数值评分（如 scarcity_score=9.2），输出模式识别和定性判断（如"行业处于 bottleneck_formation 阶段"）。

Step 间接口化

Step N 的输出通过结构化的 schema 传给 Step N+1，每个 Step 的输入输出都是可序列化的 JSON。

断点续跑

Pipeline 基础设施(Checkpoint/Trace) 每步落盘，支持独立重跑单步、跳过已完成的 Phase。检查点跨版本查找 + 过期清理。

全链路可追溯

TraceContext 记录每步的搜索/LLM/DB 调用链，支持回溯每个结论的原始证据。前端 Timeline 可视化。

16 类跨 Step 枚举 | 标准化 Term 注入
景气阶段 瓶颈类型 供给刚性 价值捕获 竞争格局 利润属性 资本开支 增长形态 约束类别 护城河 催化剂类型 风险类别

每个枚举定义在 framework/pipeline/glossary.py 中，跨 Step 共享一致的分类语义。Agent 的 system prompt 自动注入相关枚举，保证输出格式一致性。

技术实现
⚙

Checkpoint 缓存

每步完成后将 output + trace 落盘为 JSON 文件，支持独立重跑、skip_phase 参数、跨版本兼容。

📖

Glossary 枚举注入

16 类枚举的标准化定义，跨 Step 共享。prompt 注入保证各 Agent 输出一致分类，不产生歧义。

📈

Observation 框架

Pipeline 输出自动提取观察点，存储到 SQLite 观察库。前端 badge 展示机会/风险数量，Monitor 按计划定时巡检。

🔍

双源 Web 搜索

Brave Search（主） + Tavily（备），通过 Clash 代理。8 季度财报数据从 MySQL 加载，格式化为 LLM 可读结构。
