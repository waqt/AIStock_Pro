# AI 投研系统 V7.0 未来蓝图

> 记录 V6.0 设计过程中识别但搁置的架构方向，避免遗忘。V7.0 启动时以此为输入。

---

## 一、从 V6.0 到 V7.0 的本质跃迁

```
V6.0: 单次 DAG Pipeline → 输出报告
V7.0: 动态反馈网络 → 产业资本流动模拟器
```

V6.0 解决的是"一次分析多深"，V7.0 要解决的是"分析结果如何自我修正、如何随时间演化"。

---

## 二、搁置的四大方向

### 方向 1: 动态反馈网络 (自反馈产业系统)

**现状**: DAG 是单向流水线 Step1→2→3→...，推演结果不反向影响上游判断。

**V7.0 目标**:

```
Step4 发现: "电力才是真瓶颈"
  → 反向修改 Step2 行业景气排序: 提高电网权重, 降低GPU权重
  → 反向修改 Step3 产业链分析: 增加电力设备层级
  → 重新定价: 电网资产估值上调
```

**关键技术**: DAG → 有向循环图 (DCG), 收敛条件判定, 迭代终止逻辑

**复杂度**: 高。需要重构 DAGOrchestrator 的核心编排逻辑，引入反馈边和收敛判定。

---

### 方向 2: CapitalFlowAgent (资金行为层)

**现状**: 分析框架全在基本面/产业面，没有资金行为维度。

**V7.0 目标**:

```
新增 Agent: CapitalFlowAgent
输入: 股票代码 + 行业
分析维度:
  1. 主动 vs 被动资金 (ETF权重变化)
  2. 机构抱团度 (持仓集中度变化)
  3. 主题化交易 (是否被纳入 AI/新能源等主题ETF)
  4. 龙头虹吸效应 (行业内资金是否向头部集中)
  5. 融资盘杠杆 (两融余额趋势)
  6. 北向/外资配置方向
  7. 散户情绪 (雪球/东方财富讨论热度)
```

**前置条件**: 需要接入 ETF 持仓数据、两融数据、北向资金流向数据。当前无数据管线。

---

### 方向 3: 产业验证数据库 (Thesis Validation Engine)

**现状**: `thesis_validation` 只是报告输出结构，没有实际验证能力。

**V7.0 目标**:

```
组件: ValidationEngine
核心能力:
  1. 领先指标自动监控 — 定时拉取 HBM价格/GPU交期/CoWoS交期 等数据
  2. 贝叶斯更新 — 新数据到达 → 自动更新 thesis 置信度
  3. 预警触发 — 证伪信号出现 → 推送通知 "HBM紧缺论面临挑战"
  4. 验证历史 — 回顾过往 thesis 的准确率，形成系统自评
```

**数据需求**:

| 指标 | 来源 |
|------|------|
| 半导体交期 | Susquehanna / Future Horizons |
| HBM/DRAM 现货价 | DRAMeXchange / inSpectrum |
| 台积电月度营收 | 公开数据 + akshare |
| 铜/变压器价格 | LME / 上海有色 |
| 设备订单 (BB Ratio) | SEMI |

**复杂度**: 高。需要建立数据采集管道 + 存储 + 更新机制，不是一次性工程。

---

### 方向 4: 产业验证数据面板 (前端)

**现状**: 前端只有 data.html 宏观 Tab 展示基础指标。

**V7.0 目标**:

```
新增页面: validation.html
功能:
  - 当前活跃 thesis 列表 + 验证状态 (confirmed/partial/pending/falsified)
  - 领先指标实时趋势图
  - 证伪信号监控面板
  - 贝叶斯概率更新历史
  - 准确率统计 (历史 thesis 的命中率)
```

---

### 方向 5: 多智能体护城河分析系统 (来自 DeepSeek V7.0 建议)

**来源**: DeepSeek 对 Step 6 的五智能体架构建议。V6.0 的 Step 6 采用 GPT 六维权力画像 + Gemini 生命周期分轨的轻量方案，DS 的五智能体架构因数据基础设施需求过高，搁置到 V7.0。

**V7.0 目标**: 五个协同智能体替代 Step 6/7 的单 Agent 模式。

```
Agent 1: 产业侦察兵 (Scout)
  职责: 全域搜索 + 知识图谱构建
  输入: 产业名称 + 时间窗口
  输出: 全量公司候选集 + 实体关系图谱
  数据: 搜索API + 专利库 + 研报库 + 招聘数据

Agent 2: 壁垒标注员 (Labeler)
  职责: 从非结构化文本抽取护城河证据
  输出: 结构化壁垒分类 (技术/认证/资源/政策/产能/生态)
  方法: 思维链抽取 → JSON 标注 (壁垒类别/描述/时效/置信度)
  关键: 区分"当前壁垒"和"超前指标"(里程碑/加速增长/突破/批准进入下一阶段)

Agent 3: 财务绩效计算器 (Calculator)
  职责: 定量验证 + 超额利润归因
  计算: ROIC(含研发资本化调整) / ROIIC / WACC剪刀差 / 毛利率优势 / 定价权系数
  规则: 壁垒置信度高 + 超额回报>0 → "强护城河已确认"
        壁垒证据存在 + 超额回报<0 → 检查超前指标 → "护城河建设期"

Agent 4: 前瞻推演师 (Foresight Simulator)
  职责: 未来护城河形成概率评估
  方法: 催化剂事件链拼接 + 情景模拟推理 + 萌芽期护城河评分卡
  输出: 未来3年形成宽阔护城河的概率(0-100%) + 护城河动量分

Agent 5: 综合评估官 (Synthesizer)
  职责: 护城河矩阵 + 投资叙事生成
  输出: 二维象限图 (X=当前强度, Y=未来动量, 气泡=TAM, 颜色=预期差)
        + 三段论叙事 (现状/催化路径/风险与反身性)
        + 连续监控模式 (Daily Cron Job 追踪超前指标)
```

**前置条件** (V6.0 尚不具备):
- 专利数据库接入 (IPC分类号/被引次数/权利要求宽度)
- 认证注册库 (FDA/车规/航空适航 状态跟踪)
- 供应链合同/订单公告的结构化抽取
- 招聘数据 (JD爬取 → 人才密度/方向判断)
- 多源实体对齐 (同一公司在不同数据源的名称归一化)

**V6.0 过渡**: Step 6 的六维权力画像可视为 Agent 2 的简化版 (只做壁垒标注, 不建知识图谱)。Step 7 的 FinancialAuditor 可视为 Agent 3 的简化版 (只做审计, 不做 ROIC 归因)。V7.0 将它们升级为完整五智能体系统。

## 三、V6.0 到 V7.0 的过渡路径

### Phase 7.1: 数据基础设施 (2-3周)
- 建立领先指标数据采集管线 (半导体交期/DRAM价格/设备订单)
- 扩展 macro_history 表，增加行业高频指标
- 前端验证面板原型

### Phase 7.2: CapitalFlowAgent (1-2周)
- 接入两融/北向/ETF持仓数据
- 新增 Agent，集成到 DAG 末尾

### Phase 7.3: 动态反馈 DAG (3-4周)
- DAGOrchestrator 重构为 DCG (Directed Cyclic Graph)
- 反馈边 + 收敛判定 + 迭代终止
- 向后兼容现有 Pipeline

### Phase 7.4: 验证引擎 (2-3周)
- Thesis Validation Engine
- 贝叶斯更新逻辑
- 预警推送

---

## 四、不纳入原则

以下方向明确不在 V7.0 范围内:

- ❌ 实时推演 (Real-time): 当前日频/周频足够，秒级推演是过度工程
- ❌ 全自动化交易信号: 本系统定位是研究辅助，不是量化交易系统
- ❌ 全球全行业覆盖: 聚焦半导体/AI/能源等供给侧行业，不做消费品/金融等需求侧行业
- ❌ 多用户/权限系统: 保持单用户个人投研中台定位
